边界原则

机器与人工分文件

提取结果与策展结果永不写进同一个文件，重跑提取不可能破坏手写 DSL。

失败即大声

解析不了的模式进 _unresolved.json 并让 CI 失败，不允许默认值兜底。

每条记录可溯源

source.class + jar sha256，任何数字都能回到那一行 Java。

5数据模型

以卡牌为主示例；其余实体同一套「提取字段 + source + 策展 DSL」模式

5.1 卡牌记录（data/sts1/cards/red.json 中的一条）

{
  "id": "Bash",                                   // 游戏字符串 ID，全局主键
  "name": { "en": "Bash", "zh": "痛击" },
  "description": { "en": "Deal !D! damage. NL Apply !M! #yVulnerable.", "zh": "造成 !D! 点伤害。 NL 给予 !M! 层 易伤 。" },
  "upgradeDescription": { "en": null, "zh": null },   // 仅当类覆盖了升级描述
  "color": "red", "type": "attack", "rarity": "basic", "target": "enemy",
  "cost": 2,                                        // -1 = X 费，-2 = 不可打出（沿用游戏约定）
  "base":    { "damage": 8,    "block": null, "magic": 2 },
  "upgrade": { "cost": null, "damage": 2, "block": null, "magic": 1 },   // upgrade() 解析出的增量
  "keywords": [],                                   // exhaust ethereal innate retain unplayable
  "upgradeKeywords": null,                          // null = 同 keywords；否则为升级后的完整数组
  "playable": true,
  "effects": [                                      // ← 来自 red.effects.json（策展）
    { "op": "damage",     "target": "enemy", "amount": "damage" },
    { "op": "applyPower", "target": "enemy", "power": "Vulnerable", "amount": "magic" }
  ],
  "upgradeEffects": null,                           // null = 同 effects（引用自动取升级数值）；否则为完整替换列表，不是补丁
  "source": { "class": "com.megacrit.cardcrawl.cards.red.Bash", "jar": "desktop-1.0", "jarSha256": "…" }
}
!D! !B! !M! 与 NL 占位符原样保留，由引擎在渲染时替换，和原游戏一致；这也让 §8 的「文本 ↔ 数值一致性」测试成为可能。
文件划分

cards/red green blue purple colorless curse status special.json；special.json 收 tempCards / optionCards（小刀、洞察、选项卡等），color 保留游戏真实值，另有提取字段 obtainable:false；playable 仅在 cost=-2 时为 false。

升级语义（固定）

upgrade 存增量；upgradeKeywords / upgradeEffects 为 null 表示「与基础相同」，否则是完整替换而非补丁。两者都进 Schema 校验。

统一溯源对象

所有实体同一形状：{ class, jar, jarSha256 }；additionalProperties:false 下只允许这一种。

5.3 Schema 规则

JSON Schema 2020-12

每实体一份；additionalProperties:false，拼错字段立刻失败。

交叉引用校验

applyPower.power、怪物 moves[].powers[].power、addCard.card、encounters.monsters[]、startingRelic、startingDeck[] 必须真实存在。Schema 描述的是「提取 + 策展」合并后的形状，validate 自行合并后校验。

类型自动生成

json-schema-to-typescript → packages/sts-data/src/types.ts，引擎零手写类型。

风险对策

★引擎核实结论（带入子项目 2）

已用 CFR 反编译并阅读 41 个核心类（GameActionManager / DamageInfo / AbstractMonster / MapGenerator / Random / AbstractDungeon / ShopScreen / RelicLibrary / CardLibrary / MonsterHelper …）
动作队列就是引擎

全部逻辑经由一条有序动作列表（addToTop / addToBottom）+ cardQueue + WAITING_ON_USER / EXECUTING_ACTIONS 相位机。VFX / SFX / Wait / ShakeScreen 动作穿插其中，网页引擎把它们作为 UI 事件发出，模拟层保持确定性。

伤害公式

base → 施加方 atDamageGive → 姿态 → 承受方 atDamageReceive → atDamageFinalGive → atDamageFinalReceive → floor，钳到 ≥0；Java float 运算，TS 侧每步 Math.fround 以保证舍入一致。

RNG 可复现

RandomXS128（xorshift128+）+ 调用计数器，多路流（aiRng / cardRandomRng / mapRng / monsterRng / relicRng / potionRng / treasureRng / eventRng / merchantRng / shuffleRng …）由局种子派生。精确移植后可用「同一种子 → 同一张第 1 幕地图 / 同一组 Neow 选项」作为对照测试。

地图生成

MapGenerator ≈ 250 行纯算法（7×15 网格、6 条路径、祖先检查防交叉），直接移植；常量进 map.json。

需要重新切分的上帝类

AbstractDungeon 2,680 行 / AbstractCard 2,566 / AbstractPlayer 2,218 混合了状态、渲染与输入，不逐行移植。

怪物 AI 是代码不是数据

JawWorm 的 getMove：roll<25 且上一招咬合 → 56.25% 吼叫否则鞭打；roll<55 且连续两次鞭打 → 35.7% 咬合否则吼叫；其余分支类似。现有 wiki 数据「咬合后 59%/41%」是对这段结构的近似。按怪物各写一个 TS 函数。
